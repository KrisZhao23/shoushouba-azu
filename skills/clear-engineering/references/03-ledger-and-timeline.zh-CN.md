# 项目台账、时间线与可接续理解

[English](03-ledger-and-timeline.md) | [简体中文](03-ledger-and-timeline.zh-CN.md)

按需维护已有记录，使读者理解当前系统，并能定位思路或处理方法从哪个关键转折开始出错。记录不是活动流水账；已有内容足够时，不另建文件。

研究借鉴、作者与许可见[案例和来源说明](06-case-evidence.zh-CN.md#source-licenses)。本库起始稿另行组织，没有收录上游项目的原始台账或业务记录。

## 1. 内容放在读者需要的位置

| 需要理解什么 | 主要记录什么 |
|---|---|
| 当前系统怎样工作 | 目标、责任、合作、状态与约束、实现入口 |
| 为什么这样选或后来改了 | 关键判断、改变判断的依据、修正及必要证据引用 |
| 当前要做什么 | 简短待办：负责人、下一步、检查时间或触发条件 |
| 某项结论能信到哪里 | 实际来源、适用对象、验证结果与未知 |

每项事实在实际归属处维护：准确文件身份归原清单，运行证据归原输出。其他记录只保留本角色的结论、必要边界和引用，不重复展开实施经过。引用须能定位适用对象且接收方可读；原输出没有稳定可读入口时，先将足以复核的原证据保存一次到已有记录或证据位置，再统一引用，不重抄多份。这些用途可合并在现有文件，不强制新建清单或文档。

## 2. 项目识别、新建与绑定

台账属于持续维护的项目。同项目的新需求、换人、换会话、测试副本或搬移沿用原入口；副本注明基线和差异。只有目标、边界与维护责任确实独立时，才考虑另立项目。

先查已指定入口，再按需查相关 README、项目说明及引用。已有材料能承担整体解释与导航时直接复用。入口失联、权限不足或多个入口冲突，先核查可访问来源；仍无法消除歧义时提出具体确认，不当成“没有台账”另建一份。不要求搜索整台机器，也不反复索要已明确的路径。

确实缺少入口、需要持续接续且获准写入时，建立最小真实记录，可用 `PROJECT-LEDGER.md`。保留目标与范围、主要合作、有效约束、实现入口、必要未知和待办位置；无实现就说明无实现，不编造符号或补写通史。临时问答不机械建账，只读调查也可在授权内保存有接续价值的发现。

每个项目指定一个当前工程理解入口，内部按需要展开。平台共用能力在真实归属处解释，其余项目引用。入口应有整体解释，不能只是目录或要求先读全部历史。

在获准修改且实际会被读取的工作入口中登记项目范围、台账位置及路径基准。创建、登记、实际读到是不同事实；不能把触发规则只放在尚未被读取的 Skill 里便声称已接入。写台账不自动授权修改 AGENTS、启动规则或权限；写入受限时说明待保存位置与内容，不冒称完成。加载核查见[使用与观察](05-usage-and-evaluation.zh-CN.md)第 3 节。

## 3. 从解释找到实现与合作

存量按本次实际工作范围补齐、标出缺口，不把全库补档当作当前动作的前提。

项目台账或其引用的现有说明，必须以文字覆盖各项独立职责与跨边界行为。按模块、关键函数/接口或完整行为组织，读者应能找到：

| 内容 | 必须说明什么 |
|---|---|
| 实现定位 | 实际文件与函数、类、接口或注册符号；必要时附行号范围及对应快照，代码移动时更新。行号辅助定位，不能单独充当标识。 |
| 目的摘要 | 这一部分为何存在、接收什么、产生什么、承担什么责任。 |
| 依赖与耦合 | 谁提供什么、谁使用结果；共享状态由谁拥有、谁读写；共同约束及必要的先后条件。 |
| 连接方式 | 通过哪个调用、接口、事件、表或适配器连接；哪里转换数据、由谁保证什么契约、哪里产生副作用。 |
| 变化与验证 | 改这里影响哪些消费者或约束，哪些行为必须保持，相关测试或实际证据在哪里；未核实范围明确列出。 |

本次工作相关且实际存在的隐形依赖也必须写明，包括环境或当前用户读取、全局或共享可变状态、导入副作用、初始化/调用顺序、事务与资源生命周期。依赖要写出对象和关系，不能只列技术名；未查清不能写成“无依赖”。

小项目可用一段话覆盖，相关辅助函数可合并说明，不机械逐函数、逐行建档。已有代码注释或设计说明足够时直接引用；大型项目在入口概述整体关系，再链接相关说明。读者能据此定位实现、理解合作与影响并找到验证依据时即可停止展开。

## 4. 分清主张的性质

区分提议、已接受约定、实际观察、运行证据与未知。接受注明内容、范围和依据；没有反对不是接受，接受设计也不是执行授权。源码可见不等于已经运行，实现、验证和环境生效分别据实说明。

未记录不代表没有风险。历史资料缺失时，不用当前诊断冒充当时事实；无法恢复的内容保留未知。

## 5. 只记值得回查的关键转折

时间线帮助定位判断或方法在哪里出了问题：原判断是什么，哪条事实改变了它，如何修正，依据在哪里。只保留对今后理解、排错或避免重犯有用的短因果线索；普通操作、反复讨论和每轮进度不进入长期历史。

例如：“曾把服务在线视为用户可用；账号过滤证据推翻该判断；改为核验当前账号的实际入口。证据：<引用>。”这条线索足以定位问题，无需保留整份错误方案。

关键转折只写一处，可放在相关行为或任务中；项目级台账仅收录影响整体认识的部分。

## 6. 时间只写到足以定位

需要区分时，说明发生、记录、实现或验证的不同时间；未发生的事不填完成时间。不知道日期或时区就保留未知或可确认区间。时间戳不能证明因果，后写也不代表更有效。

## 7. 发现差异就修正原说明

区分记录错误或过期、实现违背有效约定、已接受设计尚未同步。按证据直接修正当前说明，不机械以代码或旧审核为准；通知真正依赖该主张的参与者。

<a id="frozen-audit-records"></a>
项目明确约定冻结的审计原件保留原文及原时点含义。审核依据引用已有批次的冻结清单、方案或原输出；持续更新的任务报告及可变行号不作为唯一冻结依据。当前报告可精简为当前有效结论、新问题和证据入口，保留适用范围、未验证项及授权边界；派单和回执引用这些位置，不复制过程。

已有审核若只绑定了持续更新的报告，先在已有可更新记录中将引用接到可核验的同一份冻结证据；确无副本时，才在原批次保存一次必要的已审原文并核对原身份。不能用当前新版冒充旧证据；无法恢复时说明缺口，不宣称绑定已恢复，也不为每次记录更新另造快照。

后续更正或复审结论在已有可更新记录中维护并引用原件，确保原入口能定位当前结论。只有实际对象、行为、风险或结论适用性的实质变化才按原审核门槛补审受影响部分；单纯精简记录或调整定位不触发重审。

符号迁移更新定位，含义变化核对受影响消费者，范围变化更新适用边界。已证伪的主张删除；仍有争议的主张只保留必要依据和待核查问题，不冒充既定事实。

<a id="record-updates"></a>
## 8. 维护时点与当前待办

小任务在原任务或交付记录写清变化、结果与必要证据即可。新增或改变职责、依赖、状态含义、连接契约，或发现原说明失准时，同步修正对应说明；已有内容仍准确就不改。普通验证结果留在任务记录；证据改变既有结论时，才更新结论归属处。入口链接仍准确就无需更新入口，不为收尾新建栏目。

外部效果未知及时记录，避免重复执行。交接前只补影响继续工作的缺口，保存后核对实际内容；受限或部分保存如实说明。

Pending 只保存当前安排：事项、负责人、下一步、检查时间或触发条件，以及必要记录链接。更新直接替换旧值，完成只撤下当前安排；仍有效的系统说明和重要未知继续保留，不复制完整报告或保留旧安排。已有台账内含待办就复用该区块，不另建清单。等待或搁置写明原因及恢复条件，不能靠改名掩盖未完成工作。

<a id="scoped-reading"></a>
**必须留存不等于每次通读。** 按当前问题分层读取：

| 场景 | 读取范围 |
|---|---|
| 首次接手或新窗口 | 项目整体摘要、当前任务停点及相关实现导航；据此定位本次职责，不通读全部详细说明与历史。 |
| 已有认识仍适用 | 当前变化及受影响说明；复用已核实的理解，不为证明“读过”重读。 |
| 实际修改或排错 | 涉及部分的目的、依赖、状态与连接契约，再核对相关代码、消费者和证据。出现跨边界影响、矛盾或关键未知时，沿具体关系扩大范围。 |

长文档先搜索标题、符号或任务标识，再读取有关段落；一次输出被截断，应缩小范围，不整份重读。上下文压缩后从当前入口和相关说明恢复缺失认识，不默认重建全库理解，也不把“以前读过”当成现在仍掌握。

能说明本次改哪里、影响谁、必须保护什么及如何验证，且没有影响本步的重要关系未查清时，停止扩读；仍需展开就明确要解决的具体疑问。中断不等于完成；结果未知时先核实外部实际效果，不能因缺少成功记录就重复动作。

## 9. 多角色和并行更新

各任务维护自己的范围和停点，共享事实维护一处。按项目既有协调规则合并；存在并行覆盖风险时，明确由谁串行合并相关段落，不以最后写入者为准。保存前比较基线，基线变化就重新合并；争议未解保留必要依据，不覆盖其他任务的有效事实。

## 10. 更新也包括删除

删除明确错误的方案正文、失效条件、被替代的安排、重复解释及无用过程。关键误判若值得今后排错，只留第 5 节的短因果线索；没有持续价值就直接删，不用归档保存另一份负担。不能靠顶部摘要掩盖正文堆积。

保留当前实现的职责、依赖与连接说明，以及仍有效的约束、尚未解除的风险、未知外部效果和不可重建的必要证据。是否删除看它还支持什么判断，不看篇幅或读取次数。一次更新足以让人继续并定位关键问题后，就停止。
